# 합성 fixture

승인된 Mock 프로파일과 예시 데이터의 버전·출처·기대 결과를 관리할 자리다. 실제 제조사 호환 데이터를 뜻하지 않는다. 생성기와 샘플은 후속 기능 작업에서 추가한다.

첫 대표 fixture `mockprofile-100-a-001.json`은 REST/JSON·기본 장비·vendor-a의 합성 사례다. 도착 순서 `1, 3, 2`와 기대 복원 순서 `1, 2, 3`, 세 번째 레코드의 절대영도 미만 격리를 기록한다. 값·필드명·프로토콜 동작은 실제 제조사 사양이 아니다.

`tonkatsu-business-v1.json`은 조리작업·안전·평가 첫 API의 합성 기준 배치와 부분 적재 경계다. 실제 장비 용량이나 제조사 사양이 아니다.

`combi-quality-load-v1.json`은 밥·고등어의 중형/대형 기준·절반 적재 비교 fixture다. 밥 기준 식재료는 각각 44kg·88kg이며, 고등어 기준은 팬당 10토막·토막당 150g과 10·20팬을 적용한 15kg·30kg이다. 절반 기준을 포함한 이 구간은 프로젝트의 합성 품질 비교 규칙으로 실제 장비 사양·정격 하중·식품 안전 기준이 아니다.

# 자동 온도 공정판정 합성 사례

`tonkatsu-process-high-v1.json`은 첫 REST/JSON Mock 프로파일과 동일한 스키마를 사용한다. `batch-a-process-high-001`에 181°C 표본을 5초 간격으로 0~20초까지 제공하여, 20초 경계에서 `HIGH_PROCESS_FAILURE`가 발생하는 경우를 재현한다. 실제 장비의 운전값이나 호환 사양이 아니다.

`jeyuk-small-process-v1.json`은 소형 볶음·교반기의 1초 원표본 걸림 경계 fixture다. 20rpm·부하율 95%가 지속될 때 5초에는 `AGITATOR_JAM_WARNING`, 30초에는 `AGITATOR_FAILURE`가 되는 기대 결과를 기록한다. 5초 전송 평균이나 실제 장비 사양을 표현하지 않는다.

`jeyuk-small-safety-v1.json`은 마지막 채소·소스 투입 완료를 1초에 기록하고, 이후 승인된 최저온도 지점의 혼합물 온도 75°C를 60초 연속 유지하는 합성 사례다. 60초에는 유지 59초로 대기하며 61초에 자동 안전 증거가 `PASSED`가 된다. 실제 장비·식품 검증 데이터가 아니다.

제육 합성 공정 규칙 `jeyuk-process-v2`는 부하율이 100%를 초과한 한 표본을 즉시 `MOTOR_OVERLOAD_TRIP`·`AGITATOR_FAILURE`로 판정한다. 정확히 100%는 트립이 아니며, 비상정지는 별도 `EMERGENCY_STOPPED` 원인을 보존한다. 실패는 같은 배치에서 정상 표본이 와도 유지된다. 이 수치는 프로젝트의 합성 컨트롤러 기본값이다.

새 Worker 판정과 모니터 상태에는 `process_rule_version`을 저장한다. 기존 무버전 판정의 재조회는 기존 결과와 v1 출처를 유지하며, 이를 v2로 바꾸지 않는다. v1/무버전 상태에서 v2 계산을 이어 쓰거나 v1 판정을 v2 업무 기록으로 적용하는 것은 거부한다. 기존 원본·판정·이벤트를 삭제하거나 덮어쓰는 마이그레이션은 수행하지 않는다. 기존 배치의 재판정이 필요하면 원본과 연결된 별도 파생 버전 및 명시적인 포인터 전환이 필요하다. 새 시연은 새로운 합성 배치 ID로 시작한다. 원천 감사도 각 판정의 규칙 버전이 현재 규칙과 다르면 현재 근거로 인정하지 않는다.
