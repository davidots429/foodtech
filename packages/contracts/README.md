# 공통 계약

첫 `mockprofile-100-a-v1` JSON Schema와 Python 계약 패키지를 추가했다. 스키마별 정규화는 온도·속도·경과시간을 유효한 십진 문자열로, 사건시각을 UTC ISO 8601로, 없는 선택적 오류 사유를 JSON null로, 출처 확장 숫자를 문자열로 만든다. 정규화 결과를 `rfc8785` 0.1.4로 직렬화하고 SHA-256을 계산한다. 업무 중복 키는 source ID·스키마 버전·record ID를 UTF-8 바이트 길이 접두어로 결합한다. 수신 ID·업무 키·내용 해시는 독립 필드다. 수치·시각·Null의 실제 적합성은 구현 후 교차 언어 시험으로 확인한다.

`jeyuk_process.py`는 승인된 제육볶음 소·중·대형 합성 프로파일의 하중·솥 표면온도·교반축 RPM·조리시간 경계와 1초 표본 기반 지속시간 판정을 제공한다. 연속 표본이 끊기면 판정기를 진행시키지 않고 호출자에 오류를 돌려주므로 5초 전송 평균으로 걸림·이탈 지속시간을 채우지 않는다. `jeyuk_mock.py`는 C# `mockprofile-110-a-001` 합성 원표본을 해석하며 출처·프로파일·필드·1초 간격을 검증한다. 이 원표본은 DynamoDB·SQS 저장과 고객 작업의 공정판정에 연결된다. 실제 제조사 사양을 뜻하지 않는다.

`jeyuk_safety.py`는 마지막 재료 투입 완료 **다음 초부터** 승인된 최저온도 지점의 교정 상태 `OK` 혼합물 온도 75°C 이상이 60초 연속인지 판정한다. 저온 표본은 연속 시간을 초기화하고, 투입 후 교정 만료는 자동 증거를 `ASSESSMENT_INCOMPLETE`로 만든다. 이 자동 증거는 최초·재검증 시 필요한 수동 탐침 검증을 대체하지 않는다.

`foodtech_contracts.recovery_reconciliation`은 격리 복원본에서 보존 중인 모든 삭제 요청에 대한 재삭제 결과를 요청별·저장소별로 대조하는 순수 판정 함수다. 현행 Registry의 전체 스냅샷·격리된 공통시각 복구세트·저장소 목록이 검증되었다는 입력을 별도로 요구하고, Capsule 누락·요청 수 불일치·실패·누락·잔존 미확인·결과 모순은 모두 부적합으로 판정한다. `NOT_FOUND`는 저장소별 확인이 완료된 경우에만 성공으로 계산한다. 이 함수는 증거의 진위를 확인하거나 삭제를 실행하지 않으며 실제 복원 환경 승격에 연결되지 않았다. Registry 확보·동시 변경 통제·저장소별 Worker·잔존 검증·감사와 배포 차단은 별도 구현이 필요하다.
